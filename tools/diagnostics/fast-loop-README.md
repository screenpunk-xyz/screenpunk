# Screenpunk standalone guard test loop

This executable source packet is available now. Default mode compiles and runs the released guard with synthetic readers; it never enumerates native processes, contacts a broker, modifies a service, installs a cask or touches a workspace/Keychain. There are no SwiftPM dependencies or separate fixture DMGs. The native mode is an explicit read-only diagnostic for the approved Studio account, using the same native calls, guard order and stage reporting as reviewed PR155. No native mode execution has occurred on the developer's personal Mac.

```sh
bash screenpunk-fast-loop.sh
```

Expected exit: `0`. Stdout is one JSON object: `mode:"fixtures"`, `passed:true`, `failureCount:0`, ten cases with `passed:true`, `nativeProcessInventoryRead:false`, `lifecycleMutations:false`, `homebrewUpgradeQualified:false`. Idle complete inventory is accepted; unknown code, approved GUI, legacy GUI, AppKit GUI presence, metadata failure, PID reuse, wrong UID and expired budgets refuse. These are real guard decisions with synthetic readers, not native Homebrew qualification.

```sh
bash screenpunk-fast-loop.sh native
```

Expected exit: `0` for an absence-proof observation, `8` for refusal. Stdout is the existing stage JSON including `diagnosticOnly:true`, `releasedProbeVersion:"1.0.5"`, `nativeAbsenceProbePassed`, `stage`, `phase`, counts, PID, Security/native returns and deadline/elapsed observations. `authorizesLifecycleMutation:false` is always retained. Do not interpret an observed pass as authorization to uninstall, or stale errno after a successful call as a new failure. Use the actual failed stage/return. Root already supplied one native diagnostic run; this reusable mode is for explicitly selected subsequent iterations, not an automatic retry or polling loop.

The default scratch root reuses `/private/tmp/screenpunk-cli-upgrade-diagnostic-2026-10-05`, with the exact implementation-chat owner marker or an existing matching JSON ownership manifest. Lexical dot/dotdot, duplicate/trailing path separators and symlink parents are rejected before any write. Unknown ownership, symlink components/output members and unsafe regular outputs are refused. The prior diagnostic's `ownership.json`, source and result remain intact; harness accounting uses `fast-loop-ownership.json`. Each run gets unique evidence JSON/compiler logs under `evidence/`. A directory lock prevents concurrent runs. Before compiler allocation, the wrapper requires at least 20 GiB free and reports disk/scratch/cache/evidence usage. It enforces a practical 128 MiB scratch budget with 32 MiB initial headroom, a 96 MiB module-cache limit, a 12 MiB evidence limit and at most 200 JSON receipts. Usage is checked again after compilation; exhausted budgets stop without deleting unique evidence or silently pruning caches. Per-run storage JSON is retained. Compiler output and the module cache are reused in the same root. These are preflight/post-build limits, not a filesystem quota on synchronous compiler writes. The environment variable `SCREENPUNK_FAST_LOOP_ROOT` can select another exclusively owned `/private/tmp` root for fixture tests; it does not redirect any native Screenpunk runtime.

The existing Apple arm64 Swift compiler/macOS SDK is required. No compiler installation, certificate creation, signing or notarization is included. Compilation creates an ad-hoc local executable; it is not a Developer ID release or an unsigned-code test. If the toolchain is missing, return that specific failure instead of changing trust settings. No quarantine stripping or Gatekeeper override is needed for locally compiled reviewed source.
