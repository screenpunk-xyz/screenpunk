# Headless build XPC service

This package builds a private macOS XPC service with App Sandbox enabled and no network entitlement. `package-xpc.sh APP_BUNDLE CODESIGN_IDENTITY VERIFIED_KIT_DIRECTORY` places the service and the already verified, catalog-derived authoring kit under `Contents/XPCServices`, signs the service, and leaves final containing-app signing to the release packager. The controller's `OfflineBuildRunner` requires its opaque `VerifiedToolchainKit` to resolve to that sealed bundle location. There is no arbitrary command path or system-Node fallback.

The version-1 XPC protocol prepares one job, uploads source files in 256 KiB chunks with per-file SHA-256, executes the fixed `bin/node --jitless scripts/build.mjs SOURCE OUTPUT` command, downloads output chunks, and releases the job. The helper rechecks the enclosing bundle seal and requires the Node executable to carry only `com.apple.security.app-sandbox` and `com.apple.security.inherit`. Source configs, dependency trees, symlinks, unsafe paths, case collisions, and files outside the snapshot are rejected. It accepts at most two jobs and one per project. `posix_spawn` creates an owned process group with close-on-exec descriptors and a four-entry environment; macOS may inject `__CF_USER_TEXT_ENCODING`. The helper bounds source to 50 MiB/2,000 files, each job stage to 256 MiB, retained log to 1 MiB, returned diagnostics to 32 KiB, output to 50 MiB/2,000 files, and wall time to 120 seconds. Cancellation and client invalidation kill the process group and clean owned jobs. Caller output is checked against returned hashes and moved into an absent staging path only after successful transfer.

`Tests/sandbox-smoke.sh` assembles an ephemeral ad-hoc signed test app using a copied system Node and a controlled script. It is a development qualification test only; it does not verify release publisher provenance or a pinned kit. The smoke test has run successfully in `/private/tmp`: the helper built through XPC and its inherited Node child was denied an outside-container file and a loopback HTTP server that answered HTTP 200 to an unsandboxed client. The temporary bundle is normally removed afterward. The shell script intentionally uses `swift build --disable-sandbox` only to coexist with Codex's own command sandbox; the runtime helper uses Apple's signed App Sandbox.

F4 still needs independent review and real-kit/compiler instrumentation. TypeScript host reads are guarded, project-selected config is refused, and esbuild imports use a custom namespace resolver whose successful `onResolve` result replaces built-in fallback. Its package-export subset is tested against synthetic packages, but the actual pinned dependency tree has not been exercised; unsupported package patterns fail closed. The package output needs the existing manifest/package validator and workspace source/head CAS before publication. The old `ScreenAuthoring.build` path remains live outside this new runner and must be retired or routed through this boundary before an F4 milestone exit. The production F1 resolver has no release authority provisioned yet; ad-hoc signing is never production trust.
