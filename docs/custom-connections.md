# Device connection setup and custom HTTP

Connection setup on managed iPad screens: Home Assistant and custom services appear directly in Settings → Connections. A connection with required:true blocks screen interaction with a setup prompt until this exact screen version is approved. Use required:false for optional features and provide an actionable setup-required state rather than a generic Unavailable label. Users configure credentials on the device; new screens/versions can reuse saved connection details only after explicit access approval. Never embed tokens, passwords, Authorization headers, or private user-specific URLs in source, manifests, examples, logs, or tool arguments.
Custom authenticated HTTP (updated native host required, iOS staging build 35 or later): declare customHTTP instead of publicHTTP or operations on the connection. Example: {"alias":"desk","required":true,"customHTTP":{"name":"Desk service","authentication":"bearer","operations":[{"name":"status","method":"GET","path":"/status","parameters":{}},{"name":"power","method":"POST","path":"/power","parameters":{"state":["on","off"]}}]}}. Authentication is none, bearer, or apiKey; apiKey also declares headerName, such as X-API-Key. The setup form asks for an origin URL, secret when needed, and explicit local-network/HTTP permission. Paths are fixed, relative to that origin; redirects and credential/destination overrides are rejected. At most 16 operations and 12 parameter keys per operation; each parameter declares up to 64 exact allowed string values. Call await screenpunk.connections.request('desk','status',{}) or request('desk','power',{state:'on'}). GET/DELETE parameters become query parameters; POST/PUT/PATCH send flat string-valued JSON. Responses must be JSON; use JSON null for empty success. Custom connections do not yet support OAuth flows, subscriptions, arbitrary request headers, arbitrary bodies, or raster responses. Do not substitute direct fetch for unsupported features. Keep writes disabled when reads are stale/unavailable; writes are never queued or replayed. A permission_required error means setup/approval is needed or credentials were rejected; device_offline means the configured service could not be reached.
Build workflow: inspect screen.json before editing, preserve all connection declarations, use the normal screen build/package tools, and inspect the resulting manifest for unchanged aliases, required flags, and exact operations. Preview responsive layouts at narrow/wide and rotated sizes. Browser preview cannot prove device-local connectivity. Deploy through the reviewed plugin flow, complete Settings → Connections setup on the device, then verify live state and user-triggered controls. Older hosts reject the new customHTTP declaration; update the host instead of removing required declarations. A successful install/render is not proof of a working connection.
